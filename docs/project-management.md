# Lightweight Project Management

This guide is optional. Delete it when the project does not need issue-based planning.

## Suggested Labels

- `bug` — Something is not working as intended
- `enhancement` — New feature or improvement
- `documentation` — Documentation additions or corrections
- `question` — More information or discussion is needed
- `help wanted` — Assistance from contributors would be useful
- `good first issue` — Suitable for a new contributor
- `blocked` — Waiting on another task, decision, or dependency

GitHub template repositories copy files, but repository labels may need to be created separately in each new repository.

## Milestones

Use milestones only when they add value. A simple approach is to create milestones matching planned releases, such as `v0.1.0`, `v0.2.0`, and `v1.0.0`.

## Workflow

1. Capture bugs and feature ideas as issues.
2. Assign a milestone when an issue belongs to a planned version.
3. Use labels for type or status, not as a substitute for clear issue titles.
4. Update `ROADMAP.md` when priorities or target versions change.
5. Update `CHANGELOG.md` when a user-visible change is completed.
